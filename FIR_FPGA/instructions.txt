│   ├── result_fifo.v           # Queues 16-bit filtered audio and serializes to bytes
│   ├── admission_control.v     # Manages block submission & hardware ready/backpressure
│   └── fpga_fir_top.v          # Top-level FPGA wrapper interconnecting the pipeline

├── constraints/                # FPGA physical and timing constraints
│   └── zedboard_pins.xdc       # Pin mappings for ZedBoard Pmod JA (3.3V) & 100 MHz clock

--------------------------------------------------------------------------------
2. FILE DESCRIPTIONS
--------------------------------------------------------------------------------

[tools/]
- filter_design.py: Computes the 129-tap linear-phase FIR coefficients for 48 kHz,
  quantizes to Q1.15 format, and exports coefficients_q15.hex.
- golden_fir_oracle.py: Exact integer oracle matching hardware arithmetic
  (accumulation, +16384 rounding bias, arithmetic right-shift 15, and saturation).
- gen_test_vectors.py: Creates verification vectors (impulse response, left/right
  isolation, saturation recovery, and two-tone passband/stopband).
- pc_mcu_streamer.py: Host PC streaming script that reads a 48 kHz stereo .wav,
  streams 256-byte blocks over USB-UART to the MCU, collects the filtered blocks,
  and saves the resulting output .wav file.
- verify_audio.py: Compares hardware-recorded output WAV against bit-exact Python
  oracle calculation and prints error statistics and match percentage.

[rtl/]
- coeff_ram.v: Double-banked memory array. The core reads from the active bank
  while incoming SPI packets load the inactive bank. Bank swaps on atomic commit.
- history_ram.v: Block RAM storing separate memory spaces for Left and Right
  channels. Contains a synchronous counter-based memory clear engine.
- mac_lane.v: Multiplies signed 16-bit operands into a 32-bit register and
  accumulates into a 40-bit sign-extended accumulator (DSP48E1 mapping).
- reduction_saturate.v: Pipelined reduction unit performing round-to-nearest
  (ties away from zero) and clamping to [-32768, 32767].
- scheduler.v: Sequencer FSM for 64-frame stereo blocks (128 samples). Manages
  modulo read/write pointers and aligns pipeline delay control flags.
- spi_phy.v: SPI Mode 0 physical interface. Uses double flip-flop synchronizers
  to prevent clock domain crossing (CDC) metastability on sclk, cs_n, and mosi.
- packet_parser.v: Interprets packets. Checks 0xA5 magic byte, decodes opcodes
  (STATUS, WRITE_COEFF, COMMIT, SUBMIT, READ_RESULT, RESET_STREAM), and checks XOR.
- input_job_fifo.v: Queues incoming samples from SPI (256 samples capacity).
- result_fifo.v: Converts 16-bit filtered audio into 8-bit bytes (Little-Endian)
  for SPI MISO reading.
- admission_control.v: Asserts fpga_ready_irq when space is guaranteed. Blocks
  jobs if result buffer would overflow.
- fpga_fir_top.v: Top-level chip wrapper interconnecting all sub-modules to I/O pins.

[tb/]
- tb_fir_core.sv: SystemVerilog unit testbench validating arithmetic blocks
  against golden hex files with 0 error tolerance.
- tb_fpga_top_spi.sv: End-to-end SPI testbench executing complete MCU transactions
  and verifying aborted packet recovery.
- fir_sva_assertions.sv: SVA checking no commit mid-job, FIFO limits, and handshakes.

[constraints/]
- zedboard_pins.xdc: Maps SPI bus and handshake to ZedBoard Pmod JA and constrains
  100 MHz primary clock.

[firmware/]
- fir_accelerator_driver.h / .c: Renesas RA6E2 C driver using FSP r_spi to write
  coefficients, poll backpressure, and process blocks.
- hal_entry.c: MCU main loop acting as a bridge between the PC UART and FPGA SPI.

3. ENVIRONMENT SETUP GUIDES
--------------------------------------------------------------------------------

A. XILINX VIVADO PROJECT SETUP (ZEDBOARD)
-----------------------------------------
1. Open Vivado and select "Create Project".
2. Enter Project Name (e.g., "zedboard_fir_accelerator") and target directory.
3. Project Type: Choose "RTL Project" (leave "Do not specify sources" unchecked).
4. Default Part Selection:
   - Switch to the "Boards" tab.
   - Filter/Search for "ZedBoard" (Select ZedBoard Zynq Evaluation and Development Kit).
   - Alternatively, in the "Parts" tab, select part: "xc7z020clg484-1".
5. Add Design Sources:
   - Click "Add Files" and browse to the "rtl/" directory.
   - Select all 11 synthesizable files:
     admission_control.v, coeff_ram.v, history_ram.v, input_job_fifo.v,
     mac_lane.v, packet_parser.v, reduction_saturate.v, result_fifo.v,
     scheduler.v, spi_phy.v, and fpga_fir_top.v.
   - Ensure "Scan and add subdirectories" is enabled.
6. Set Top Module:
   - In the "Sources" hierarchy window under "Design Sources", right-click
     "fpga_fir_top.v" and click "Set as Top".
7. Add Constraints:
   - Click "Add Sources" -> "Add or create constraints".
   - Browse to "constraints/" and select "zedboard_pins.xdc".
8. Verification of Project Setup:
   - In Vivado Flow Navigator, click "Run Synthesis".
   - Ensure synthesis finishes cleanly with zero syntax errors.

B. RENESAS E2 STUDIO PROJECT SETUP (RA6E2 FSP)
----------------------------------------------
1. Launch e2 studio with your desired workspace path.
2. Select "File" -> "New" -> "RA C/C++ Project".
3. Select "Renesas RA C/C++ Project" and click Next.
4. Set Project Name (e.g., "ra6e2_fir_bridge") and click Next.
5. Board and Device Selection:
   - Device: Select "R7FA6E2BB3CFM" (or choose your exact RA6E2 Evaluation Kit from the Board list).
   - Toolchain: Select "GNU ARM Embedded" (GCC for ARM Cortex-M).
   - Click Next.
6. Project Template:
   - Choose "Bare Metal - Minimal" (or "No RTOS").
   - Click Finish. This opens the FSP Configuration screen ("configuration.xml").
7. Configure Stacks in FSP ("Stacks" tab):
   a. Add SPI Master Stack:
      - Click "New Stack" -> "Connectivity" -> "SPI (r_spi)".
      - In Properties -> Settings:
        * Name: g_spi0
        * Channel: 0 (or target channel)
        * Operating Mode: Master
        * Clock Phase: Data sampled on odd edge (Edge Odd / Mode 0)
        * Clock Polarity: Low when idle (Low / Mode 0)
        * Bitrate: 10000000 (10 MHz)
        * Bit Width: 8-bit
        * Callback: g_spi0_callback
   b. Add UART Stack:
      - Click "New Stack" -> "Connectivity" -> "UART (r_sci_uart)".
      - In Properties -> Settings:
        * Name: g_uart0
        * Channel: Target channel routed to onboard USB-UART bridge
        * Baud Rate: 921600
        * Callback: g_uart0_callback
8. Configure GPIO Pins in FSP ("Pins" tab):
   - Ports -> Select GPIO pin for FPGA_CS_PIN (e.g., Port 1 Pin 3):
     * Mode: Output - Initial High
   - Ports -> Select GPIO pin for FPGA_READY_PIN (e.g., Port 1 Pin 4):
     * Mode: Input
9. Generate Code:
   - Click the "Generate Project Content" button (top right of FSP configurator).
10. Import Custom Source Files:
    - Copy "fir_accelerator_driver.h", "fir_accelerator_driver.c", and "hal_entry.c"
      from "firmware/" into the generated "src/" folder inside your e2 studio project.
    - Confirm files compile cleanly by clicking the "Build" (hammer) icon.

4. PROCEDURE: SIMULATION TESTING (MODELSIM)
--------------------------------------------------------------------------------

STEP S1: GENERATE COEFFICIENTS AND TEST VECTORS (PYTHON)
-------------------------------------------------------
1. Open terminal inside tools/:
   cd tools/
   python filter_design.py
   python gen_test_vectors.py
2. Verify that coefficients_q15.hex and data/vectors/*.hex are generated.

STEP S2: RUN CORE ARITHMETIC UNIT SIMULATION (tb_fir_core.sv)
-------------------------------------------------------------
1. Open ModelSim and load project (esd_fir_project.mpf).
2. Add files to the project:
   - All 11 files in rtl/
   - tb/tb_fir_core.sv
   - tb/fir_sva_assertions.sv
3. Click "Compile All" and verify all files compile without syntax errors.
4. Go to the "Library" tab, expand "work", right-click "tb_fir_core" -> "Simulate".
5. In Transcript prompt, run:
   run -all
6. Verification criterion:
   Confirm transcript outputs [PASS] for all 4 test vectors (impulse, isolation,
   saturation, two-tone) with 0 errors.

STEP S3: RUN CHIP-LEVEL SPI SYSTEM SIMULATION (tb_fpga_top_spi.sv)
------------------------------------------------------------------
1. In the "Library" tab, right-click "tb_fpga_top_spi" -> "Simulate".
2. In Transcript prompt, run:
   run -all
3. Verification criterion:
   Confirm transcript outputs:
   - [PASS] SPI Audio Block 0 verified: All 128 samples match golden reference!
   - [PASS] SPI Parser recovered cleanly from aborted packet!
   - ALL TOP-LEVEL SPI TESTS PASSED SUCCESSFULLY!


--------------------------------------------------------------------------------
5. PROCEDURE: HARDWARE IMPLEMENTATION & REAL-TIME TESTING
--------------------------------------------------------------------------------

STEP H1: BUILD & PROGRAM THE FPGA (VIVADO)
------------------------------------------
1. In the configured Vivado project, click "Generate Bitstream" in Flow Navigator.
2. Check Timing Summary: Confirm WNS >= 0.000 ns and WHS >= 0.000 ns at 100 MHz.
3. Connect PC USB cable to ZedBoard PROG port (J17), switch SW8 ON.
4. In Hardware Manager, click "Auto Connect" -> "Program Device" using fpga_fir_top.bit.
5. Verification criterion: Blue DONE LED on ZedBoard is illuminated solid.

STEP H2: HARDWARE WIRING (ZEDBOARD PMOD JA <-> RENESAS RA6E2)
-------------------------------------------------------------
Power off both boards. Connect female-to-female jumper wires:

Signal Name      ZedBoard JA Pin     Package Pin     RA6E2 Connection
--------------------------------------------------------------------------------
spi_cs_n         Pin JA1             Y11             Configured GPIO Output (P103)
spi_mosi         Pin JA2             AA11            MOSI0 (g_spi0)
spi_miso         Pin JA3             Y10             MISO0 (g_spi0)
spi_sclk         Pin JA4             AA9             RSPCK0 (g_spi0)
GND              Pin JA5 / JA11      GND             Board Ground (GND)
fpga_ready_irq   Pin JA7             AB11            Configured GPIO Input (P104)

*CRITICAL*: Never omit the common GND connection.

STEP H3: FLASH MCU BRIDGE FIRMWARE (E2 STUDIO)
----------------------------------------------
1. In e2 studio, build the project (Project -> Build Project).
2. Connect the RA6E2 evaluation board to the PC via its dedicated USB debug port.
3. Click "Run" -> "Debug" (or "Run") to flash the compiled executable to the MCU.
4. Once flashed, resume/run the target so the firmware enters hal_entry() loop.

STEP H4: REAL-TIME STREAMING & RUNTIME TEST (PC)
------------------------------------------------
1. Connect RA6E2 USB port to PC and identify COM port in Device Manager (e.g. COM5).
2. Open terminal in tools/:
   cd tools/
   python pc_mcu_streamer.py COM5 input.wav filtered_output.wav
3. Monitor progress counter to 100%. The script writes filtered_output.wav.

STEP H5: HARDWARE OUTPUT BIT-EXACT VERIFICATION
----------------------------------------------
1. In tools/, run verification script against the software oracle:
   python verify_audio.py input.wav filtered_output.wav
2. Verification criterion:
   Confirm output prints:
   [RESULT] PASS: Hardware output is 100% BIT-EXACT to the Golden Model!
   (0 mismatched samples across all processed blocks).
